# Terminal memory on COSMIC Wayland

Mechanically verified measurement for `eon-zlf`, 2026-09-08. This compares
installed complete terminal applications with one inert child, at **120×30**.
It is not a 120×40 result, a terminal-library benchmark, or a GPU-memory result.

Eon and EonTerm used about **71 MiB idle** and **92–99 MiB with loaded
history**, compared with Foot at **11 MiB / 24–25 MiB** and the installed
Ghostty snap at **183 MiB / 188–195 MiB**. These are process-tree PSS figures
excluding the identical workload child, on this warm, actively used host.

The report covers **219 measured launches**: 55 each for Eon, EonTerm, and Foot,
and 54 for Ghostty. Every product/workload cell has **n=9**, except plain output
in Eon, EonTerm, and Foot, which has **n=10**. The expanded 240-run plan was
interrupted because windows stole desktop focus. The report meets the original
minimum of ten fresh launches per terminal; it does **not** claim a completed
ten-per-cell experiment. Final analysis required no further GUI launches.

## Method and boundaries

Each product/workload cell has nine or ten fresh application processes.
Product and workload order were shuffled within each repetition using Python's
`random.Random(20260908)`. Each launch had fresh private runtime, configuration,
cache, and state directories. The host's shared page cache and running
applications were preserved. This is a warm host with cold per-run application
roots; it is not an isolated cold-boot comparison.

The identical child was `/usr/bin/python3 child.py CASE WORKLOAD`. It entered
raw mode, waited for the harness to confirm a 120×30 PTY, hid the cursor,
cleared the screen, wrote the complete payload, and requested cursor position
with `CSI 6 n`. Sampling followed its matching reply and a fixed three-second
settle. The PTY size was checked again after settling. Empty requires `1;1`;
all other cases require `30;120`. No terminal output follows the reply.

The primary measure sums `/proc/PID/smaps_rollup` PSS over the launched process
and all descendants, excluding the identical workload child. PSS apportions
shared pages among mappings; adding RSS would count shared pages repeatedly.
Private memory here sums `Private_Clean`, `Private_Dirty`, and
`Private_Hugetlb`. See the [Linux proc documentation](https://docs.kernel.org/filesystems/proc.html).

Every sampled process had `SwapPss=0`, although the host was using swap.
The CSV retains every numeric rollup field, PID/start-time identity, executable,
command line, sample time, role, and PTY geometry. It also includes the workload
child, so totals can be reconstructed with or without it. Shared compositor,
portal, and D-Bus services outside the owned descendant tree are excluded under
the same rule for every product. Mapped graphics-related system pages can appear
in PSS; these measurements do not count dedicated GPU allocations.

Reported values are MiB, calculated from kernel KiB / 1024. Ranges are empirical
p05–p95, with linear interpolation at `(n - 1) × p`; they are not confidence
intervals. Nine or ten runs give limited tail precision. Component medians need
not sum to the median total, which is calculated from each run's process sum.

## Workloads

All nonempty lines occupy exactly 120 terminal cells. There are 30 lines in
`screen` and 10,030 lines in each loaded case: 10,000 lines of scroll input plus
30 visible lines. Lines are separated by CRLF with no final newline. Empty
contains no printable payload.

For line number `i`, the prefix is five zero-padded decimal digits and a space.
Plain appends the first 114 characters of
`("abcdefghijklmnopqrstuvwxyz0123456789 " * 4)`. Styled uses the same text
with bold, foreground palette index `16 + i % 216`, and background index
`232 + i % 24`, then resets SGR. Unicode appends `("e\u0301ΩЖ" * 38)`:
combining acute, Greek omega, and Cyrillic Zhe, all covered by DejaVu Sans Mono.
Mixed cycles plain, styled, and Unicode by `i % 3`. Screen uses plain lines.

These deterministic payloads use the categories motivating the upstream
libghostty comparison; they do not reproduce its exact bytes. CJK, emoji,
hyperlinks, images, and throughput are outside this measurement.

Orbit's installed runtime fixes history at 16 MiB. Ghostty was configured to
the same byte budget; Foot was configured for 10,000 history rows. A byte budget
is not a row-count guarantee, and retained-history counts were not independently
measured. Loaded labels therefore describe identical emitted content, not a
claim that all products retain exactly 10,000 history rows. Foot also rounds its
history allocation capacity. These are explicit limits on retained-state
comparisons. See the [Ghostty configuration reference](https://ghostty.org/docs/config/reference)
and the installed Foot 1.16.2 `foot.ini(5)` manual.

Typography was DejaVu Sans Mono at 16 logical pixels, with 18-pixel rows and
opacity 1. Eon/EonTerm used `font_size=16` and `line_height=1.125`; Foot used
`pixelsize=16`, `line-height=18px`, and `dpi-aware=no`; Ghostty used 12 points

of DejaVu Sans Mono, not byte-identical font files; exact font hashes and pilot

COSMIC overrode the planned 120×40 startup geometry. With user authorization,
tiling was temporarily disabled. Initial-height constraints still prevented
that grid without repeated interactive window resizing, so the experiment uses
a common 120×30 grid. Requested dimensions compensate observed chrome:
Eon 118×30, EonTerm and Foot 120×30, Ghostty 121×33. Every accepted sample checks
the resulting PTY at 120×30. These are measured launch inputs for these exact
artifacts and compositor, not general configuration recommendations.

The user's desktop remained active. Focus, occlusion, and background activity
were not fixed. The cursor-position reply establishes parsing completion, not
proof that every final frame was presented; the fixed settle interval does not
eliminate that distinction. Shared-code PSS can vary with other applications,
including pre-existing Eon and Foot processes; private-memory figures provide a
second view. Fresh short runs establish neither long-term growth nor a leak bound.

Three Foot runs received stray input before their cursor-position replies:
`matrix-03-foot-empty` (`30` hex), `matrix-06-foot-screen` (`0d`), and
`matrix-08-foot-screen` (`7f7f`). The raw-mode child had echo disabled and only
read these bytes; they were not printed. The CSV's `input_prefix_hex` preserves
the contamination. Keeping all completed runs avoids selecting by memory value.
Excluding those three changes Foot's empty median from 11.212 to 11.207 MiB
(n=8) and screen median from 11.589 to 11.557 MiB (n=7); the product ordering
is unchanged. This sensitivity check does not make desktop focus controlled.

No result should be extrapolated to another compositor, GPU, package build,
scale, platform, grid, or upstream macOS library measurements.

## Reproduction and evidence

Portable process observations: [CSV](eon-zlf-2026-09-08.csv). This generated
file is evidence, not handwritten project LOC.

The disposable scripts, exact payloads and hashes, launch arguments and isolated
configuration, complete rollups, pilot maps and logs, seeded order, environment,
binary/font hashes, rejected cases, and cleanup records are retained at:

```text
/home/lucca/.local/state/eon/proofs/eon-zlf-20260908/
```

`matrix.py` calls `run.py` for each seeded product/workload pair. `run.py`
launches `foot -c CASE/foot.ini CHILD...`,
`ghostty --config-default-files=false --gtk-single-instance=false ... -e CHILD...`,
`eonterm -- CHILD...`, or `eon run -- CHILD...`. Every case's `launch.json`
contains its full argv and overridden environment. Full Eon selects its temporary
directory through `eon tab directory`; SIGINT is sent only to that launch's fzf
child to finish the picker. The final tree must contain exactly supervisor,
Orbit, Venus, and workload child. Controls must contain terminal and child.

The installed entrypoints above, fixed payload recipe, configurations below,
per-process argv in the CSV, and retained per-run `launch.json` records define
the launch inputs. Reproducing a native sample also requires a way to preserve
the user's desktop focus. The retained launch harness has no such guarantee;
**do not rerun `run.py` or `matrix.py` on an active desktop as-is**. A different
compositor would require a separate cohort.

Offline analysis launches no terminal:

```sh
python3 /home/lucca/.local/state/eon/proofs/eon-zlf-20260908/analyze.py
```

The analyzer checks that all 219 result labels match the first 219 entries of
the retained 240-case schedule, all 24 cells have their stated counts, each tree
has the expected roles, each numeric field matches its original rollup, every
sample has the required grid/reply/settle and zero swapped PSS, and every sampled
process identity appears in its cleanup record. It exports 658 process rows and
reconstructs the PSS totals from that CSV. A separate calculation checked the
reported medians and interpolated percentiles directly from the exported rows.

Each launch used a private mode-0700 `/tmp/ezlf-*` directory for its working
and runtime directory, with separate XDG configuration/cache/state/data and Eon

socket, `GDK_BACKEND=wayland`, and `LC_ALL=C.UTF-8`; HOME and the host session bus
were inherited. Inherited EON/VENUS/ORBIT settings, X11 display, loader overrides,
Wayland debug, and activation tokens were removed. This isolates application
state but does not isolate desktop focus or shared host services.

Geometry failures were rejected before collecting a PSS result; their processes
were cleaned up and the same matrix cell retried. The interrupted final launch
produced no result and is excluded. No result was rejected based on its memory
value. All pilot results are excluded. Cleanup records identify
only benchmark-owned processes; Eon generations are stopped through each
isolated runtime's CLI. Temporary configuration, runtime roots, sockets, and
windows were removed, and the original per-workspace tiling settings restored.
The recorded end-of-measurement cleanup preserved all ten baseline process
identities. This follow-up launched no benchmark or desktop-control processes.
